---
title: "Artifacts have names, and lint is a report module"
date: "2026-10-31"
category: "feature"
verdict: "arreglo"
---

**What it was**: the lint artifact was called `lint.cc.json`, but it is not a cc.json —it carries its

own `schemaVersion`, not `meta.apiVersion`— so the suffix promised an interoperability it does not

have. Its earlier name, `lint.json`, stopped being written and **was still read in seven places** —the

web app twice, two CLI functions, `serve`, the MCP and the desktop app, the last one with its own

copied constant—, each with its own list of names. This repo had both files at once: the one an old

server left behind and the one the analysis writes. And there were more questions around it with no

written answer: `report.json` and `head-report.json` with no declared relation, and local state

(`chains`, `scopes`, `parse-cache`, `preferences`) looking just like a document meant to be shared.

**What changes**: [ADR 0100](../../adr/0091-0100/0100-los-nombres-de-los-artefactos.md) sets the rule.

`.cc.json` is the **format**, not ownership: only `snapshot.cc.json` and `rest.cc.json`, the cc.json

2.x documents that open elsewhere. `report.json` is the report, and its pieces are

`<module>.repmod.json` —*report module*—; lint becomes `lint.repmod.json`. `head-report.json` stays.

Local state carries no suffix. And **one name, one place**: the package that writes an artifact

declares its name and consumers import the constant. No compatibility: the seven old-name readers and

both alias constants are gone, and yesterday's `lint.json` or `lint.cc.json` is ignored instead of

half-read.

**Why this way**: a name that lies costs code. Every alias meant repeating the list of names in

another module and keeping two paths for the same thing; and a folder with two names for one artifact

makes it impossible to know which one wins. At 0.x a local artifact is regenerated by measuring again:

backwards compatibility is not worth seven readers.

**Verified**: `codarch analyze .` with the freshly built CLI leaves `.codarch/lint.repmod.json` (525

files measured, 0 findings) and the folder is back to its nine files, with no `lint.json` or

`lint.cc.json`. The tests that pinned the old-name read now pin the opposite —the server answers 204,

the MCP says “unmeasured”, the capture paints without lint— and `format.test.ts` pins the name. Lint

with no messages over 570 files, a clean typecheck, **1396 tests** green and `site:build` with 281

pages.

**Verdict**: fix.
